## U-20261116-02 · 2026-11-16 · Language server no longer crashes on lint findings · #bugfix #lsp

- **Why**: the language server raised `AttributeError: 'dict' object has no attribute 'level'` on any document the linter had something to say about. `lint_action` returns dicts (`rule`, `severity`, `message`, `location`); the server read attributes. The tests only opened invalid JSON, `[]` and `{}`, none of which produce a finding. Reproduced with `[["WR_quit"]]` before the fix.
- **What**:
  - **Findings**: read as dicts. `warning` is LSP severity 2, `info` 3.
  - **Lines**: a finding sits on the line where its action starts (`action_lsp/_positions.py` scans the text for the elements of the action list); before, the action index was used as the line. A document-level finding (`meta`) is on line 0.
  - **Object documents**: `{"meta": …, "webdriver_wrapper": […]}` is linted like the executor runs it; before, every object was an error.
  - **Completion**: only `WR_*` names. The executor's allowlisted builtins (`print` …) were offered too.
  - **Notifications** the server does not know (`didSave`, `$/cancelRequest`) get no reply; an unknown request still gets `-32601`.
  - **`didClose`** publishes an empty diagnostics list for the document.
- **Files**: `je_web_runner/action_lsp/server.py`, `je_web_runner/action_lsp/_positions.py`, `test/unit_test/test_action_lsp.py`, `README.md`, `README/README_zh-CN.md`, `README/README_zh-TW.md`, `docs/source/Eng/doc/integrations/integrations_doc.rst`, `docs/source/Zh/doc/integrations/integrations_doc.rst`.
- **Evidence**: `pytest test/unit_test/test_action_lsp.py test/integration_test/test_action_lsp_subprocess.py` 22 passed. mypy reports nothing for the two modules; flake8 reports only `_read_message` (complexity 11), which this change did not touch (`progress.md` #23).
- **Open items**: hover, position-aware completion, formatting and quick fixes are `progress.md` #31.
